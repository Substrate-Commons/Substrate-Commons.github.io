Monte-Carlo, made permanent

Walk once.
Replay forever.

A substrate is a mesh. A simulator walks it. We freeze that walk — trajectories, boundary contact, and the susceptibility field — into a compact replay pack (.rpk): a lossless bottleneck of the Monte-Carlo process, from which any acquisition decodes instantly. And because the walks are additive, anyone can contribute — the error bars only ever go down.

The intermediate representation

One walk, every acquisition.

Producing a converged random walk through realistic microstructure is the expensive step; evaluating a pulse sequence against a stored walk is nearly free. So the useful unit is not a signal — it is the walk itself. The replay pack is the lossless bottleneck between the two: everything upstream (which mesher, which simulator, how many spins) collapses into it, and everything downstream (which sequence, which field, which contrast) decodes out of it — with no re-simulation, ever.

The federated commons

Error bars that only fall.

Monte-Carlo shards are additive and commutative: independent walks of the same substrate pool into one larger ensemble, in any order, and the noise floor drops as 1/√ΣN. That turns a substrate into a shared, crowd-generatable resource. Publish a first shard; anyone with spare compute — a laptop, a free Kaggle GPU, a spot VM — can lower its error bars. Nothing regresses. When a substrate's measured floor clears its target, it is frozen, snapshotted, and citable — a permanent, converged answer the whole field can reuse instead of re-running.

Signed shards & contributor credit

A receipt for the compute you gave.

The commons only works if contribution is attributable. So every contributor signs the shard they submit — an Ed25519 signature over the shard's content hash, recorded in the pack's manifest, never mixed into the trajectory data itself. The physics stays untouched and byte-identical; the provenance rides alongside it. The signing key is unforgeable, but a name is not — so named credit requires registering your public key once, via a pull request to the contributors/ registry, exactly like an SSH or commit-signing key. GitHub authenticates the PR author, so no one can put your name next to their key. From there the bank knows exactly who walked how many walkers into which substrate — and credits them, by name, on the solved substrate. Not as authors of the work you did with it, but as contributors to the resource: a permanent, verifiable receipt for having helped build a piece of the commons that will outlast any one paper.

Three layers, one direction

A contract, an engine, a commons.

Dependencies flow one way and never back. The format is a contract anyone can implement; the engine walks and replays it; the commons federates it. Each layer is useful on its own.
